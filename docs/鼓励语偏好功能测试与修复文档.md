## 三、未通过项 · 问题描述与复现

### F1 · 开关未全量生效（P0）

**前置条件**：设置 → 鼓励语偏好，关闭「显示鼓励语」。

**操作步骤**：
1. 关闭「显示鼓励语」，保存。
2. 回目标总览，完成当日**第 1 个**任务。
3. 再完成**第 2 个**及以后的任意任务。

**预期结果**：开关关闭后，任何任务完成都不再显示任何鼓励语提示。
**实际结果**：第 1 次完成未提示（符合）✅；第 2 次起**仍弹出 right-bottom toast 鼓励语**（`又完成一项，稳扎稳打。`）❌。

**现象定位**：`TaskItem.vue` 的 `doComplete` 对非首个任务（`beforeDoneCount > 0`）无条件调用 `encStore.random()` 并 `message.success()` 弹 toast，**未读取 `settings.enabled`**。

---

### F2 · 三视图鼓励语行为不一致（P0）

**前置条件**：开关开启，频率「首任务+里程碑」。

**操作步骤**：
1. 在**目标总览**完成一个任务。
2. 在**目标树**完成一个任务。
3. 在**日历**完成一个任务。

**预期结果**：三个视图行为一致（同一套完成语义 + 鼓励语）。
**实际结果**：
- 目标总览：只弹**鼓励语弹框**，无完成弹框；
- 目标树：只弹**完成/补完成弹框**，无鼓励语；
- 日历：只弹**完成/补完成弹框**，无鼓励语。

**现象定位**：目标总览的 `TaskItem.doComplete` 与 `DashboardView` 走 `taskStore.completeTask()`（会触发鼓励语），而 **GoalTreeView / CalendarView 直接调用各自的完成/补完成处理（未统一走 taskStore + encouragement）**，导致鼓励语逻辑在目标树、日历完全不触发。

---

### F3 · 展示频率三种模式无差异（P0）

**前置条件**：开关开启，文案风格任意，任务 ≥ 3 个。

**操作步骤**：
1. 频率切「每次完成」，连续完成多个任务，记录鼓励语出现次数。
2. 频率切「首任务+里程碑」，重复以上操作。
3. 频率切「仅里程碑」，重复以上操作。

**预期结果**：三种模式鼓励语出现次数明显不同（每次 / 首任务+里程碑 / 仅里程碑）。
**实际结果**：三种模式表现**完全一致**（均为「首任务全弹、后续 toast」，与所选模式无关）。

**现象定位**：`taskStore.maybeShowEncouragement()` 虽定义了频率分支，但实际完成链路（特别是目标树/日历绕过 taskStore）未接入，因此频率参数未起作用。

---

### F4 · 文案风格"专业理性 / 极简克制"无内容差异（P0）

**前置条件**：临时在弹框/toast 加 `[风格:xxx]` 探针（测试探针）。

**操作步骤**：
1. 风格切「温暖鼓励」，完成一个任务，记录正文与探针。
2. 风格切「专业理性」「极简克制」，重复操作。

**预期结果**：三种风格正文文字明显不同（口吻区分）。
**实际结果**：探针 `[风格:xx]` 随选择变化（说明设置已下发），但**正文文字完全一致**（如 `七天的坚持，你对目标的掌控更强了。`）。

**现象定位（双层）**：
1. 迁移 `016` 新增 `style` 列时，**所有既有预设文案 style 全部保持 `warm`**，无任何 `professional` / `minimal` 文案；
2. 后端随机抽取 `randomEncouragement` 等命令**未按 settings.style 过滤**，因此无论选什么风格，抽到的都是 `warm` 文案。

---

### F6 · 庆祝动画缺失（P1）

**前置条件**：构造「全部目标完成」场景（预留任务统一完成）。

**操作步骤**：
1. 开启「庆祝动画」，触发全部目标完成。
2. 关闭「庆祝动画」，再次触发。

**预期结果**：开启时应有彩带/粒子等庆祝动画；关闭时仅普通提示。
**实际结果**：两次都仅显示普通「全部目标完成！」弹框，**无任何彩带/粒子动画**。

**现象定位**：`CelebrationModal.vue` 中 `celebration_animation` 未驱动 canvas-confetti 动画（或动画被条件截断，未实际触发）。

---

### F8 · 显示 emoji 开关无效（P1）

> 定义确认（用户）：开关开启时，由**前端在鼓励语文案前自动附加 emoji**；关闭时纯文字。

**前置条件**：开关开启。

**操作步骤**：完成任一任务触发鼓励语，观察文案。

**预期结果**：文案前出现对应主题 emoji（如 🎉 ✊ 🔥）。
**实际结果**：文案为纯中文，**始终无 emoji**；切换开关无任何变化。

**现象定位**：全代码库中 `emoji_enabled` 仅被写入 settings 被保存，**无任何逻辑读取它来添加/剥离 emoji**；预设文案本身也不含 emoji。该开关当前为**空操作**。

## 四、问题定位分析（技术根因）

| 功能 | 根因 | 涉及模块 |
| --- | --- | --- |
| F1 | 非首任务的 toast 分支未做 `settings.enabled` 守卫 | `src/components/TaskItem.vue` |
| F2 | 完成/补完成的触发入口未统一（目标树、日历绕过 `taskStore`） | `GoalTreeView.vue` / `CalendarView.vue` / `taskStore.ts` |
| F3 | 频率逻辑接入点缺失——鼓励语展示未统一收敛到单一入口 | `taskStore.maybeShowEncouragement` 未在目标树/日历触发 |
| F4 | ① 预设文案 style 全为 `warm`；② 后端抽取未按 style 过滤 | `016_encouragement_style.sql` / `encouragement.rs` |
| F6 | 庆祝动画参数未驱动 confetti | `CelebrationModal.vue` |
| F8 | `emoji_enabled` 无消费者（前端装饰逻辑缺失） | `encouragementStore.ts` / `App.vue` |

**统一收敛建议（横切）**：鼓励语的"触发—频率—开关—emoji装饰—展示"应**集中在 `taskStore`（或专门反馈层）单一入口**完成，所有视图（总览/目标树/日历）的完成、补完成操作一律调用该入口。这样 F1/F2/F3/F8 一次性收口，避免各视图各自实现导致的分叉与遗漏。

## 五、具体修复建议与技术方案

> 按"先收敛、再补齐字段、再装饰"的顺序实施。

### 5.1 【F1/F2/F3 收口】统一完成与鼓励语入口

- 让 `GoalTreeView`、`CalendarView` 的完成/补完成**统一调用 `taskStore.completeTask()` / `backfillTask()`**，删除各自本地完成逻辑（参照 F2 修复——这与既有 `06 修复建议`中"统一弹框交互"一致）。
- 鼓励语展示**统一收敛**到 `taskStore.maybeShowEncouragement()`，在函数内依次判断：
  1. `settings.enabled`（关 → 直接返回，F1 修复核心）；
  2. 频率 `aggressive / normal / sparse` 决定是否触发（F3 修复核心）；
  3. 成功后写入 `pendingEncouragement`，由 **App 级居中弹框（App.vue）统一展示**（满足"鼓励语要用居中弹框"的附加要求）。
- 删除 `TaskItem.doComplete` 中非首任务的 toast 鼓励语分支（或改为只负责兜底提示，不再独立弹鼓励语）。

### 5.2 【F4】按风格过滤文案

1. 将一批预设文案的 `style` 置为非 `warm`（新增 SQL 修复脚本或一次性 UPDATE），确保三种风格各有可用文案；**注意**：修改既有迁移文件会触发 SQLx checksum 校验失败（见项目经验：`_fix_mig016.py`），故应新增`017`迁移或使用数据修复脚本，而非改写 `016`。
2. `encouragement.rs` 的 `randomEncouragement` / `randomEncouragementByStreak` / 待补充的庆祝接口：将 `settings.style` 传入 SQL 作为 `WHERE style = ?` 过滤；无当前风格文案时回退 `warm`。
3. 前端 `random()` / `randomByStreak()` 等调用可传 `settings.style`。

### 5.3 【F8】前端 emoji 装饰

- 在 `encouragementStore`（或 `maybeShowEncouragement`）中新增 `decorate(text)`：当 `settings.emoji_enabled` 时按 `level`/触发源前置一个 emoji（如 `normal→🎉`、`advance→🌟`、`celebration→🏆`），关闭时原文返回。
- `App.vue` 展示 `pendingEncouragement.text` 前套用 `decorate`。

### 5.4 【F6】庆祝动画

- 在 `CelebrationModal` 中，当 `settings.celebration_animation` 为真时触发 `canvas-confetti` 彩带动画；否则仅显示弹框。核对 confetti 依赖已在 `package.json` 引入。

### 5.5 清理临时测试探针

- 移除此前为测试加入的临时标记：`App.vue` 的 `[测试标记] 当前风格` 标签、`TaskItem.vue` toast 的 `[风格:xxx]` 前缀及其相关 computed（`currentStyleLabel`/`styleColorMap`/`styleLabelMap`）。

## 六、修复验证方法与预期结果

| 项 | 验证方法 | 预期结果 |
| --- | --- | --- |
| F1 | 关闭开关后完成第 1、2、3 个任务 | 全程不再出现任何鼓励语（弹框与 toast） |
| F2 | 在总览/目标树/日历各完成、补完成一次 | 三视图行为一致；完成弹框与鼓励语弹框按同一语义弹出 |
| F3 | 三频率模式各连续完成多任务 | 「每次完成」每次都弹；「首任务+里程碑」仅首任务+达里程碑弹；「仅里程碑」仅里程碑弹 |
| F4 | 三风格各触发一次 | 探针（若保留）与正文均随风格明显变化；正式场景观察文案口吻可区分 |

**回归注意**：修改/新增 SQL 迁移后，如遇到 SQLx checksum 校验失败，按项目既有经验运行 `_fix_mig016.py`（或对应修复脚本）后再启动 `npm run tauri:dev`；开发期仅允许单实例运行（多实例会因日志文件竞争报 `os error 5`）。

## 七、修复实施规范（操作后必做）

每次修复完成后，执行：
1. 关闭本次启动的 `npm run tauri:dev` 相关进程与服务；
2. 删除修复过程产生的临时脚本、日志、缓存（含 `_fix_mig016.py` 运行后残余，如确为一次性则清理）；
3. 复核端口无残留监听（`1420/1421/5173` 等），确认环境处于干净、稳定状态。
