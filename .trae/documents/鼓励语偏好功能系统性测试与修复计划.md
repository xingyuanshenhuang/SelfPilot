### 2.2 已知缺陷（代码走查发现）

> 注意：这些是代码层面的静态结论，正式结论以测试结果为准。

- **P0 / 高频 · 开关不生效**：`taskStore.completeTask()` 未判断 `encStore.settings.enabled`。关闭「显示鼓励语」后，完成当日首个任务仍会触发鼓励语弹窗。仅 `DashboardView.onMounted` 的挫折检测依赖了 `enabled`。
- **P0 / 高频 · 频率模式完全未生效**：「每次完成 / 首任务+里程碑 / 里程碑」三种 `frequency` 设置为空实现，前端/后端均未据其做触发控制，完成首个任务永远只触发一次。
- **P0 / 中 · 风格切换无效果**：`style`（warm/professional/minimal）仅被存储与校验（settings.rs），但 **`encouragements` 表本身无 `style` 列**、`Encouragement` 实体（[models.rs](file:///d:/Desktop/SelfPilot/src-tauri/src/db/models.rs#L492-L507)）无 style 字段，后端抽取**不做任何 style 过滤**，前端也无渲染差异 → 切换风格文案不变。**修复前置工作：需先为每条鼓励语打上风格标签，才能区分归属风格。**
- **P0 / 中 · emoji 开关无效果**：`emoji_enabled` 仅存值，无 `stripEmoji`、无后端处理 → 开关无实际作用。
- **P1 / 高 · 庆祝动画缺失**：`CelebrationModal.vue` 中 canvas-confetti 代码被整体注释，且依赖 `canvas-confetti` 未安装 → 开启「庆祝动画」也无粒子动画，仅 static modal + 顶部渐变条。
- **P1 / 高 · 目标树/日历绕过触发逻辑**：`GoalTreeView.handleCompleteTask/handleConfirmBackfill` 与 `useTaskBatch.batchComplete` 直接调用 `taskApi`，**未经 `taskStore`**，故在目标树、日历中完成/补完成任务**不会弹出鼓励语**。与「三个视图交叉测试」目标不符。
- **中 · 补完成不一致**：`TaskItem.doBackfill` 走 `taskApi.backfillTask()`，不触发鼓励语（可能符合语义，需确认设计预期）。
- **中 · 非首任务 toast 未受碍开关**：`TaskItem.doComplete` 对非首任务显示 `encStore.random("complete_normal")` toast，未判断 `enabled`。
- **中 · 补弹框统一性问题**：各视图补完成弹框实现分散，需在交叉测试中核对关闭/确认交互。

### 2.3 设计预期（PRD §4.2 模块七、Sprint 5）

- 完成当日**首个任务**后弹出鼓励文案。
- 全部目标完成 → 庆祝鼓励语 + 庆祝弹窗（含动画）。
- 接近/超越历史最长连续天数 → milestone 鼓励语。
- 频率模式应控制鼓励语出现频次：`aggressive`(每次完成) / `normal`(首任务+里程碑) / `sparse`(仅里程碑)。
- 文案风格影响文案来源与渲染风格；emoji 开关控制文案中 emoji 显示。

## 6. 修复实施计划 (对应需求第 4 部分 + 用户确认的「测试+文档+修复」范围)

以下修复基于已发现的代码缺陷拟定；**以修复文档（第 5 节）为准**，若测试发现新问题则一并纳入。每项完成后按「第 7 节清理规范」执行。

### 修复项 R1 — 总开关生效（P0/高）
- **范围**：`taskStore.ts`、`App.vue`、`TaskItem.vue`。
- **方案**：抽取统一函数 `taskStore.maybeShowEncouragement()`（内部先校验 `encStore.settings.enabled` 与 `frequency`），`completeTask()` 中仅在校验通过时设置 `pendingEncouragement`；`TaskItem.doComplete` 非首任务 toast 增加 `enabled` 判断。
- **验证**：关闭开关后完成首任务无弹窗；开启后恢复。

### 修复项 R2 — 频率模式生效（P0/高）
- **范围**：`encouragementStore.ts` / `taskStore.ts`（前端 gating）。
- **方案**：按 `frequency` 实现触发策略：`aggressive`=每次完成均尝试、`normal`=仅首任务+里程碑、`sparse`=仅里程碑/全部完成；里程碑判断复用现有 `randomLongestStreakEncouragement`/`checkLongestStreakMilestone`。
- **验证**：三模式各完成多任务，核对触发/不触发次数。

### 修复项 R3 — 文案风格生效（P0/中）

> **用户明确要求**：在修复文案风格之前，**先为鼓励语打上风格标签**，使每条文案可区分到底属于哪种风格。R3 拆分为「前置打标」与「风格生效」两步。

**R3-前置 · 鼓励语 style 打标（本步骤必须先完成）**
- **范围**：新增迁移 `migrations/016_encouragement_style.sql`；`Encouragement` 实体（models.rs:492）；前端 `types`、`EncouragementView`。
- **方案**：
  1. 新增迁移：`ALTER TABLE encouragements ADD COLUMN style TEXT NOT NULL DEFAULT 'warm';`。
  2. 迁移内为现有预设文案（migration 015 的 52 条 + 可能存在的 longest_streak 文案）分配合适的 style 标签（`warm`/`professional`/`minimal`）。
  3. 为让三种风格**可区分**，评估补充若干 `professional`/`minimal` 风格文案；确保每个等级（至少 normal/advanced/highlight/celebration 主要等级）都有足量文案供风格过滤。
  4. `Encouragement` 实体增加 `style` 字段（sqlx::FromRow 对应 SELECT 含该列）；`Add/Update Encouragement` 输入支持自定义风格（保持向后兼容，默认 `warm`）。
  5. 前端 `types/index.ts` 增加 `style` 字段；鼓励语库视图（`EncouragementView`）展示/可编辑风格标签，便于用户管理与区分。
- **验证**：迁移可安全应用（校验和一致执行，若旧库需先跑校验修复脚本）；鼓励语库每条文案可见其 style 标签；三风格均有文案可查。

**R3-本体 · 风格生效**
- **范围**：`encouragement.rs`（后端按 style 过滤）、前端渲染差异（对应 F5）。
- **方案**：
  1. 后端在各抽取路径（`pick_by_level`、按 streak/最长连续、庆祝）按当前 `settings.style` 过滤候选文案；当该风格文案不足时降级到其他风格/全量，保证不空弹。
  2. 前端「温暖鼓励」风格按设计规范呈现字体/色系/排版差异（`App.vue` 弹窗与 CelebrationModal 的视觉变量）。
- **验证**：切换 warm/professional/minimal 后，弹出的文案明显归属对应风格；温暖风格渲染符合规范。

### 修复项 R4 — emoji 开关生效（P0/中）
- **范围**：前端 `components`（文本渲染层）。
- **方案**：实现 `stripEmoji()`/emoji 过滤工具，在展示鼓励语文案时依据 `emoji_enabled` 决定是否保留 emoji，并对渲染弹窗/Dashboard banner 生效。
- **验证**：关闭 emoji 后文案中 emoji 消失。

### 修复项 R5 — 庆祝动画启用（P1/高）
- **范围**：`CelebrationModal.vue`。
- **方案**：安装 `canvas-confetti` + `@types/canvas-confetti`，恢复并启用 `playConfetti()`/@watch 调用，遵循 `animationEnabled` 控制；评估动画资源占用与时长（需求含「持续时间及资源占用情况」）。
- **验证**：开启动画出现彩带粒子；关闭不出现；动画不卡顿。

### 修复项 R6 — 目标树/日历统一走任务 Store（P1/高）
- **范围**：`GoalTreeView.handleCompleteTask/handleConfirmBackfill`、`useTaskBatch.batchComplete`。
- **方案**：改为调用 `taskStore.completeTask()`/`taskStore.backfillTask()`（若存在），保留局部更新；若 `taskStore` 无 backfill，补充统一方法。确保三个视图鼓励语触发一致。
- **验证**：目标树、日历完成/补完成任务后弹窗行为与目标总览一致（受 F1/F2/F3/F7 控制）。
