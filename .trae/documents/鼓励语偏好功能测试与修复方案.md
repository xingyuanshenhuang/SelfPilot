# 鼓励语偏好功能测试与修复方案

## 一、摘要

对设置视图「鼓励语偏好」的 8 项配置进行了系统性测试，覆盖「目标总览 / 目标树 / 日历视图」三个视图。测试采用**确定性代码路径静态追踪 + 前端类型检查 + 后端编译验证**的方式完成（GUI 运行时交互需按本文档验证方法人工复现确认）。

**结论：8 项配置中仅 2 项真正生效（显示鼓励语开关可保存、庆祝动画可切换弹窗类型），其余 6 项（触发、展示频率、文案风格、温暖风格渲染、全部完成庆祝受控、emoji）均存在实现缺口；三个视图中仅「目标总览」能触发鼓励语弹窗，「目标树」「日历视图」因直接调用 `taskApi.completeTask` 完全绕过全局鼓励逻辑，属于核心缺陷。**

## 四、未通过项目的详细问题描述与复现步骤

### 4.1 显示鼓励语（#1）—— 总开关失效

**问题描述**：在设置中关闭「显示鼓励语」后，完成今日首个任务仍会弹出鼓励语弹窗。

**根因**：鼓励触发逻辑 [taskStore.ts#L49-L91](file:///d:/Desktop/SelfPilot/src/stores/taskStore.ts#L49-L91) 在 `beforeDoneCount === 0` 时**无条件**执行鼓励抽取并写入 `pendingEncouragement`；弹窗层 [App.vue#L118-L146](file:///d:/Desktop/SelfPilot/src/App.vue#L118-L146) 的 watch 也**未校验** `encStore.settings.enabled`。

**复现步骤**：
1. 设置 → 鼓励语偏好 → 关闭「显示鼓励语」。
2. 切换到「目标总览」，完成当日第一个任务。
3. 预期：不出现鼓励弹窗；实际：仍弹出「今日首完成！」。

### 4.2 展示频率（#3）—— 三种模式均不生效

**问题描述**：设置「每次完成 / 首任务+里程碑 / 仅里程碑」后，弹窗行为无任何差异——始终表现为「今日首任务」触发一次。

**根因**：`frequency` 仅在 [settings.rs](file:///d:/Desktop/SelfPilot/src-tauri/src/commands/settings.rs#L112-L119) 被**校验并持久化**，运行时 [taskStore.ts](file:///d:/Desktop/SelfPilot/src/stores/taskStore.ts#L38-L94) 与鼓励抽取命令 **从未读取** `settings.frequency`。`grep` 全仓确认 `frequency` 仅在 `SettingsView.vue / models.rs / settings.rs / backup.rs` 出现，无任何运行时消费。

**复现步骤**：
1. 设置中选择「每次完成（aggressive）」。
2. 目标总览中连续完成 2、3、4 个任务。
3. 预期：「每次完成」模式下第二个任务起应继续出现鼓励反馈；实际：仅第一个任务弹窗，其余任务只弹普通成功 toast，与频率设置无关。
4. 再切到「仅里程碑（sparse）」，完成首个本地任务。
5. 预期：非里程碑任务不弹窗；实际：仍弹「今日首完成！」。

### 4.3 文案风格 / 温暖风格（#4、#5）—— 无差异化

**问题描述**：将风格切换为「专业理性 / 极简克制 / 温暖鼓励」，展示的鼓励语内容没有任何变化。

**根因**：后端抽取 [encouragement.rs#pick_by_level](file:///d:/Desktop/SelfPilot/src-tauri/src/commands/encouragement.rs#L51-L137) 仅按 `level`、时段 `context_tags` 过滤，**无 style 维度**；`style` 仅作配置持久化。前端渲染 [App.vue#L271-L272](file:///d:/Desktop/SelfPilot/src/App.vue#L270-L272) 直接输出 `pendingEncouragement.text`，无风格化处理。

**复现步骤**：
1. 设置中分别在三种风格间切换并保存。
2. 目标总览完成首任务观察文案。
3. 预期：不同风格文案基调应不同；实际：随机结果完全一致，风格切换无效果。

### 4.4 庆祝动画（#6）—— 无实际动画

**问题描述**：开启「庆祝动画」后新增「庆祝弹窗」，但**无任何彩带/粒子动画**；关闭后回退普通弹窗（此项有效）。

**根因**：[CelebrationModal.vue#L31-L51](file:///d:/Desktop/SelfPilot/src/components/CelebrationModal.vue#L31-L51) 中 `canvas-confetti` 动画整体被注释，且依赖未安装（`package.json` 无该依赖）。

**复现步骤**：
1. 令全部目标进度达到 100%。
2. 在目标总览完成当日该目标的首个任务，触发庆祝弹窗。
3. 预期：出现庆祝动画；实际：仅静态卡片（奖杯 + 成就数据），无动画。

### 4.5 全部目标完成庆祝（#7）—— 受控性缺陷

**问题描述**：全目标完成庆祝逻辑本身可触发，但**不受显示开关与频率约束**，且在目标树/日历视图完全不触发。

**根因**：逻辑位于 `taskStore.completeTask`（[L52-L62](file:///d:/Desktop/SelfPilot/src/stores/taskStore.ts#L52-L62)），依赖 `checkAllGoalsComplete()`，但该入口仅由「目标总览」的 `TaskItem` 调用；且流程未校验 `enabled`/`frequency`。

**复现步骤**：
1. 设置中**关闭**「显示鼓励语」。
2. 让全部目标达成 100%，在目标总览完成首任务。
3. 预期：关闭后不应弹任何弹窗；实际：仍弹出庆祝弹窗。

### 4.6 显示 emoji（#8）—— 完全未实现

**问题描述**：关闭「显示 emoji」后文案中 emoji 仍原样显示（或本无 emoji 控制）。

**根因**：前端渲染与后端抽取均未读取 `emoji_enabled`（`grep` 仅在 UI/类型/后端读取函数出现，无消费点）。既无 emoji 添加机制，也无剥离逻辑。

**复现步骤**：
1. 关闭「显示 emoji」。
2. 完成首任务查看文案。
3. 预期：文案隐藏 emoji；实际：开/关一致，配置不生效。

### 4.7 【核心缺陷】目标树 / 日历视图不触发鼓励语

**问题描述**：这是最严重的缺陷——在「目标树」或「日历视图」完成任务，**任何情况都不会出现鼓励语弹窗与 toast**。

**根因**：唯一触发全局鼓励的入口是 `taskStore.completeTask()`，全仓 `grep` 确认**仅被 [TaskItem.vue#L91](file:///d:/Desktop/SelfPilot/src/components/TaskItem.vue#L91) 调用**（用于目标总览今日列表）。而：
- 目标树：[GoalTreeView.vue#L855-L868](file:///d:/Desktop/SelfPilot/src/views/GoalTreeView.vue#L855-L868) `handleCompleteTask` 直接调 `taskApi.completeTask`，补完成 `handleConfirmBackfill` 同理；
- 日历：[CalendarView.vue#L132-L144](file:///d:/Desktop/SelfPilot/src/views/CalendarView.vue#L132-L144) `quickComplete`、[#L347-L377](file:///d:/Desktop/SelfPilot/src/views/CalendarView.vue#L347-L377) `handleBatchComplete` 均直接调 `taskApi.completeTask`。

均绕过了 `taskStore.completeTask`，因此不写入 `pendingEncouragement`，App.vue 无从得知。

**复现步骤**：
1. 切换到「目标树」，完成任一任务 → 仅 "任务已完成" toast，无鼓励语。
2. 切换到「日历视图」，完成/补完成/批量完成任一任务 → 仅 "已完成" toast，无鼓励语。

## 五、问题定位分析

### 5.1 单一职责被破坏：鼓励逻辑与「完成动作」耦合在 `taskStore.completeTask`，但未被所有完成入口复用

- 前端共有 4 处任务完成入口：`TaskItem.doComplete`（✅ 走 `taskStore.completeTask`）、`GoalTreeView.handleCompleteTask`、`CalendarView.quickComplete`、`CalendarView.handleBatchComplete`（❌ 三处直连 `taskApi.completeTask`）。
- 负责鼓励触发的代码只内置在 `taskStore.completeTask` 中，未下沉为通用函数，导致「目标任务总览之外」的完成路径天然丢失鼓励语。

### 5.2 配置参数「只存不读」

`enabled / frequency / style / emoji_enabled` 四个参数形成了完整「保存 → 回读」闭环（SettingsView → store → API → settings.rs → DB），但在**运行时链路（taskStore 触发、App.vue 渲染、后端抽取）零消费**。仅 `celebration_animation` 在 [App.vue#L128](file:///d:/Desktop/SelfPilot/src/App.vue#L128) 被读取一次（用于选择弹窗类型）。

### 5.3 触发策略硬编码为「今日首任务」

鼓励触发门槛写死为 `beforeDoneCount === 0`，与用户所选「展示频率」无映射关系，也导致：
- 非首任务永远只有 toast，无法满足「每次完成」；
- 首任务永远弹窗，无法满足「仅里程碑」。

### 5.4 庆祝动画依赖未引入

`canvas-confetti` 未安装，动画代码整体注释，导致「庆祝动画」开关形同虚设。

### 5.5 数据模型缺 style 维度

`encouragements` 表无 style 字段（`context_tags` 仅含时段/等级），无法按风格抽取，是「文案风格」无法落地的结构性前提。

## 六、修复建议与技术方案

> 建议按下面 1→5 顺序实施，均为独立可验收的改动。遵循项目约定：改动尽量集中、复用既有入口、不动无关代码。

### 6.1 统一任务完成入口（必须先做，解除 4.7）

把所有完成路径收敛到 `taskStore.completeTask`，鼓励逻辑就自动统一。

- 目标树 `handleCompleteTask`：改为调用 `taskStore.completeTask({ task_id, actual_qty })`，返回值继续走原有局部更新（`goalStore.updateTaskLocally` + `refreshProgressForGoalChain`）。
- 日历 `quickComplete` 与 `handleBatchComplete`：同样改调 `taskStore.completeTask`；批量时注意「只触发一次鼓励」——因 `taskStore.completeTask` 内部基于 `beforeDoneCount` 判定首任务，批量连续调用仅首个会触发，天然满足。
- 补完成（目标树 `handleConfirmBackfill`、日历补完成）目前**全仓无鼓励逻辑**，按需求「补完成弹框应能触发鼓励」需在补完成路径补充——建议新拆 `taskStore.backfillTask` 或在补完成处显式 `encStore.random(enc+source) + pendingEncouragement`。

**验收**：三视图完成/补完成均能看到一致的鼓励反馈（默认 `normal` 频率下）。

### 6.2 让总开关真正生效

- 在 [taskStore.ts#completeTask](file:///d:/Desktop/SelfPilot/src/stores/taskStore.ts#L38-L94) 内、鼓励抽取前守卫：

```ts
const { enabled, frequency } = encStore.settings;
if (enabled) {
  /* 原 encouraging 触发块 */
}
```

- 并在 [App.vue watch](file:///d:/Desktop/SelfPilot/src/App.vue#L118-L146) 入口加 `if (!encStore.settings.enabled) { taskStore.clearPendingEncouragement(); return; }` 作双保险。
- 需将 `encStore`（`useEncouragementStore()`）注入 `taskStore` 或改由 `completeTask` 接收 `settings` 参数，避免 store 间循环依赖（推荐后者，注入 `settings`/`frequency` 等入参）。

**验收**：关闭开关后任何视图完成均不弹鼓励。

### 6.3 实现展示频率（核心）

新增一个纯函数（如 `stores/taskStore.ts` 或 `utils/task.ts`），将「是否展示鼓励」抽象为可测函数：

```ts
function shouldShowEncouragement(beforeDoneCount: number, isMilestone: boolean, frequency: Frequency): boolean {
  if (frequency === "aggressive") return true;          // 每次完成
  if (frequency === "sparse")   return isMilestone;     // 仅里程碑
  return beforeDoneCount === 0 || isMilestone;          // 首任务 + 里程碑
}
```

- `isMilestone` = 全部目标完成 / 触发 longest_streak 里程碑（后端已有 `checkLongestStreakMilestone`）。
- 在 `completeTask` 中：先算 `milestone = allComplete || streakMilestone != null`，再按上表决定是否弹窗；`aggressive` 时非首任务也应补充非 modal 级鼓励反馈。

**验收**：
- `aggressive`：每个完成都出现鼓励；`normal`：仅首任务+里程碑；`sparse`：仅里程碑（普通首任务不弹）。

### 6.4 实现文案风格 + emoji

结合 5.5，风格需数据模型支撑。推荐两种方案：

**方案 A（后端，推荐）**：迁移新增 `encouragements.style` 列（`warm|professional|minimal|any`），并为现有文案打标签（可用文本关键词启发式回填，或按入库批次指定）；后端 `random_*` 命令接收 `style` 参数，`pick_by_level` 增加 `AND (style = ? OR style = 'any')`，无匹配时回退全风格。前端 `random*` API 透传 `encStore.settings.style`。这将让三种风格真正差异化。

**方案 B（前端轻量，快速落地 emoji）**：新增 `utils/text.ts`，提供 `stripEmoji(text)`；渲染时按 `emoji_enabled` 决定是否剥离：

```ts
displayText = computed(() =>
  taskStore.pendingEncouragement
    ? (encStore.settings.emoji_enabled
        ? taskStore.pendingEncouragement.text
        : stripEmoji(taskStore.pendingEncouragement.text))
    : "",
);
```

在 [App.vue 普通弹窗](file:///d:/Desktop/SelfPilot/src/App.vue#L270-L272) 与 [CelebrationModal.vue#L89](file:///d:/Desktop/SelfPilot/src/components/CelebrationModal.vue#L89) 统一使用 `displayText`。

**验收**【emoji】：开启时保留 emoji，关闭时文案中 emoji 被剥离。**【风格】**（方案 A）三风格抽取的文案基调不同。

### 6.5 补齐庆祝动画

- `npm i canvas-confetti && npm i -D @types/canvas-confetti`。
- 取消 [CelebrationModal.vue](file:///d:/Desktop/SelfPilot/src/components/CelebrationModal.vue#L31-L51) 中 `playConfetti` 与 `watch` 的注释，并在 `playConfetti` 内以 `props.animationEnabled` 守卫（已具备）。

**验收**：开启庆祝动画且全部目标完成时出现彩带/粒子动画；关闭时无动画（回退普通弹窗）。

### 6.6 遗留说明

- 里程碑计数口径（如第 3/7 天连续达标）用户文档未明确是否应作为 `normal`/`sparse` 的「里程碑」，当前实现以「全部目标完成 + longest_streak 接近/超越」为准，如需天数里程碑请补充明确口径后扩展 `isMilestone`。
- 上一个会话遗留的 `_fix_mig016.py` / 旧库 `selfpilot.db` 若存在校验和问题，应先在独立终端执行修复再启动应用，避免干扰本功能回归测试（见项目 memory：`_sqlx_migrations` 校验和不匹配会导致启动 panic）。
